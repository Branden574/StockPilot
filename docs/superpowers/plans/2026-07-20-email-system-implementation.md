## Repo-specific pinned decisions

1. **Stack:** TS template-literal HTML (matches existing mail stack — `templates.tsx` / `order-requests.ts`). New module `apps/web/src/lib/email/es/`: `tokens.ts` (port of es-tokens light/dark/status/SPEC — values verbatim), `registry.ts` (all 28 entries: id, family, cat, from, replyTo, subject builder, preheader builder, footer type, motion asset, flags; static text byte-identical to `EMAILS`; `rec:` refinements as code comments only), `components.ts` (+`components/*.ts` if cleaner) — the shared partials listed in the prompt, matching archetype markup exactly (email-shell, brand-strip, status-pill ×7, hero-slot, headline+serif turn, cta-row, link-fallback, info-card, detail-grid/row, item-table, order-timeline, banner, event-card, rental-asset-card, kpi-card, action-list, workspace-card, help-row, preview-banner, internal-strip, footer ×4). Family template files land in later units (`families/security.ts` etc.).
2. **Transport:** extend `sendEmail()` (`lib/email/resend.ts`) with optional `from`, `replyTo`, `headers` (keep full back-compat — old templates keep sending until each family migrates). Registry senders (security@/orders@/rentals@/schedule@/digest@/portal@/tickets@stockpilotusa.com) ride the domain-verified Resend config; the shipping step live-verifies one send per new from-address, and if Resend rejects a sender we fall back to RESEND_FROM_EMAIL with the registry display name and flag it — do not silently drop the sender design.
3. **Assets:** hosted from `apps/web/public/email/` at `https://stockpilotusa.com/email/...` (verify the exact prod-asset origin the existing `emailLogoImg` uses and match it). Logo: `logo-mark-light.png` + `logo-mark-dark.png` exports. Motion: `public/email/motion/<id>@2x.gif` (+`clock-arc@2x.gif` overdue variant), embedded per archetype (`width=528 height=194`, alt text from MOTION_GLOBAL.blocked pattern, sunk card behind).
4. **Motion pipeline (E2):** `scripts/email-motion/` — per-hero static HTML page (hero SVG + the es keyframes from the package, 1200×440 sunk-bg canvas composed per motion-board.html), Playwright frame capture, GIF assembly (gifski or ImageMagick+gifsicle, install via brew if absent), enforcing per-MOTION duration/loop (play-once → loop=1; ×N → N; infinite → 0), frame 1 = complete resting composition (MOTION_GLOBAL.firstFrame — for play-once animations that means END state first), size caps per MOTION row (≤250/300/400KB). A validation script asserts dims/size/loop for all assets and runs in the email test suite. GIFs bake the LIGHT sunk background (#eeece5) — dark-mode clients show a light hero card; flagged as accepted trade-off (no APNG-only per MOTION_GLOBAL).
5. **Dispatch wiring:** each family unit re-points its existing senders (14 call sites catalogued in the session's email inventory) to the new renderers WITHOUT changing trigger logic, suppression, or preference checks. Latent (`packing`, `staged`) + concepts (`support-received`, `support-resolved`): template + registry entry + render test, exported behind `ES_LATENT`/`ES_CONCEPT` flags, `// LATENT: dispatch decision pending (see policy audit)`, NO dispatch path.
6. **Policy flags (surface, don't decide):** rentals have no preference backend → use ESSENTIAL footer at ship time + entry in the final owner-decisions list ("rental classification decision"); dead settings toggles (email_low_stock/email_po_status/email_team_invites) → flagged, untouched; public-order suppression divergence → flagged. List-Unsubscribe + List-Unsubscribe-Post headers on every preference-controlled email (reuse the mig-0222 machinery already on order emails/digest).
7. **Tests (every family):** render with the registry's sample world adapted to real merge params; stress cases (long org/item/denial reason, missing first name → "Hi —", missing ETA); assert no `undefined`/`null`/`{{`/raw UUID in output; HTML ≤102KB; subject/preheader equality against registry; footer type per category; List-Unsubscribe presence per cat. Litmus/EoA is unavailable — approximate with the checklist + Playwright light/dark/375px screenshot renders (saved for owner review) and flag client-matrix testing as owner-runnable.
8. **Constraints:** no emojis anywhere; no Co-Authored-By trailers; conventional commits per family; do not redesign or reword — registry text is normative.
