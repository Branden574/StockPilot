# Real Per-Row Sparklines on the Inventory + Books Tables

**Date:** 2026-05-08
**Status:** Approved (proceeding to implementation)
**Owner:** Branden Vincent-Walker

## Goal

Replace the synthetic noise generated by `syntheticSeries(seed, base)` in `apps/web/src/components/inventory/inventory-table.tsx:96-110` with real movement-derived data, and let users toggle the sparkline between **quantity-on-hand trend** and **movement count per day**. Books inherit the change automatically because they share the `InventoryTable` component.

## Scope

- **In:** the "14-day" sparkline column on `/dashboard/inventory` and `/dashboard/books`
- **Out:** sparklines on the dashboard, item detail, or movements pages (already real or unrelated). No DB schema changes. No new dependencies.

## User-visible behavior

1. Each row's sparkline now reflects real data from `stock_movements` over the last 14 days.
2. The column header reads **14-day** with a small dropdown chevron. Clicking it opens a popover with two radio options:
   - **Quantity trend** (default)
   - **Move count**
3. Selection persists in `localStorage` under key `stockpilot:inventory:sparkline-mode`. Same selection applies to every row across both tabs (items + books).
4. Items with zero movements in the last 14 days render as a flat line at their current quantity (qty-mode) or at zero (move-mode).

## Architecture

### New service function

In `apps/web/src/server/services/inventory.ts`:

```ts
export interface ItemTrend {
  /** Length 14, oldest → newest. End-of-day quantity for the item. */
  qtySeries: number[];
  /** Length 14, oldest → newest. Number of movements on that day. */
  moveSeries: number[];
}

export async function getItemTrends(
  items: Array<{ id: string; quantityOnHand: number }>,
  options: { ctx?: ServiceContext } = {},
): Promise<Map<string, ItemTrend>>;
```

- Single round trip: `select item_id, quantity_change, created_at from stock_movements where organization_id = $org and item_id in (...) and created_at >= now() - 14d`
- Buckets per item per day client-side
- Caller (the inventory + books page) already has `quantity_on_hand` for every visible item from `inventorySvc.list()` — pass that in as a `Map<itemId, currentQty>` to avoid a duplicate `inventory_items` round trip
- Walks backward day-by-day to derive `qtySeries`; counts rows for `moveSeries`

Approximations (same caveats as `getDashboardHistory`):
- Items deleted in the window aren't visible — their movements are still in the table but the row isn't in our scope, so they're naturally excluded
- `quantity_change` may be a positive or negative integer; sum directly

### Page wiring

`apps/web/src/app/(dashboard)/dashboard/inventory/page.tsx` and `/dashboard/books/page.tsx`:

- After `inventorySvc.list(...)` resolves, call `getItemTrends(items.map(i => i.id))`
- Pass the resulting `Map<string, ItemTrend>` into `<InventoryTable trends={...} />`
- One extra query per page load. Cost is bounded by visible items × 14 days.

### Component changes

`apps/web/src/components/inventory/inventory-table.tsx`:

- Add prop `trends?: Map<string, ItemTrend>` (optional — defaults to flat lines if not provided so old callers keep working)
- Add `useState<'qty' | 'moves'>('qty')` for the active sparkline mode
- On mount, hydrate state from `localStorage.getItem('stockpilot:inventory:sparkline-mode')`; on change, write back
- New small popover component (built on existing Radix Popover, same pattern as the filter dropdowns shipped today) anchored to the column header
- Per-row Sparkline source switches between `trends.get(item.id)?.qtySeries` and `trends.get(item.id)?.moveSeries` based on mode
- When `trends` is undefined or the lookup misses, fall back to `Array(14).fill(qtyMode ? item.quantity_on_hand : 0)`
- Delete the `syntheticSeries` function and its TODO comment

### What stays the same

- `Sparkline` UI primitive (`apps/web/src/components/ui/sparkline.tsx`) — no changes
- All existing filter / sort / pagination behavior
- Row click targets, bulk actions, status pills

## Edge cases

- **No movements in the window for an item:** flat line at current qty (qty mode) or zero (moves mode)
- **Item with 0 current qty and no movements:** flat line at zero — degenerate but honest
- **Item created today with one movement:** day 13 reflects that move; days 0-12 show the qty before today's first movement (computed by reverse-walking — could be 0 if the only movement was the initial seed)
- **`localStorage` unavailable** (private browsing edge case): default to `'qty'`, mode resets each render — acceptable
- **Mixed item types in view (`itemType=all`):** trends function doesn't care about item type; works the same

## Decision log

| Decision | Why |
| --- | --- |
| Single helper returning both series instead of two functions | One query for both modes; toggling is instant on the client |
| `localStorage` for preference, not URL or DB | Preference, not filter; URL would clutter, DB requires a profile column |
| Default mode = quantity trend | Most actionable for operators ("is stock heading up or down?") |
| Fall back to flat line, not synthetic noise | Honest representation of "no movement" |
| Build the dropdown from existing Popover primitive | No new dep; matches today's filter dropdowns |
