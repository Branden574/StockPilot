## catalogLoader

HEADLINE: NO — the public order page (/r/[token]) does NOT reuse the internal storefront catalog LOADER. It has its own admin-client query in src/server/services/public-catalog.ts (`getPublicBookCatalog`). (3) AVAILABILITY
Both sides ship gross quantityOnHand + summed open reservations, and the CLIENT computes available = max(0, quantityOnHand - reservedQuantity). Reservations: sum of stock_reservations.quantity where released_at IS NULL, per item (internal :442-448/:467-473; public :102-108/:126-132). Public UI: public-book-card.tsx:43 `const available = Math.max(0, item.quantityOnHand - item.reservedQuantity);` (out = <=0, "low" badge <=10). Staleness: both catalogs 60s cached; both docs note the submit path re-validates fresh (public-catalog.ts:24-36; orders-new-catalog.ts:336-340), so counts are advisory.

(5) EXACT DIVERGENCE STILL NEEDED FOR A FULLY SEPARATE PUBLIC QUERY + SCHEMA
The query divergence already exists (separate select list, separate cache key/tag, books-only filter, no accessKey dimension, deferred thumbnails). What remains coupled and would need to change for a real separate schema:
a) Type: public payload still `satisfies CatalogItem[]` (public-catalog.ts:171) — the internal interface forces carrying price/reorderPoint/rackLabel/charterName/charterCode as nulls/0 in every RSC row (types.ts:20,30,31). A `PublicCatalogItem` should drop those 6 dead fields (price, reorderPoint, rackLabel, charterName, charterCode, imageUrl-if-always-null) — safety today depends on remembering to null them; a narrower type makes leaking cost a compile error.
b) Consumers: public-v2 components import the internal type (public-orders-v2.tsx:31 imports CatalogItem + AvailabilityFilter/SortKey from '@/components/orders/v2/*') — they'd need to consume the narrowed type; PublicBookCard/PublicCartRail only read the safe fields already.
c) buildAisles is copy-pasted verbatim in page.tsx:307-334 vs orders-new-catalog.ts:532-559 — dedupe into a shared pure module (NOT into orders-new-catalog.ts, which must stay untouched per the perf constraint; put it next to types.ts or in the public service).
d) Cache hygiene on any shape change: bump 'public-book-catalog-v2' → v3 (established discipline, :174-175) and, if wiring invalidation, fix the tag to the documented per-warehouse `public-catalog:${warehouseId}` form (currently static 'public-catalog', :176).
e) Optional parity gap: public catalog is excluded from the prewarm cron — first anonymous visitor per 60s window per warehouse pays the cold path.
