## Prioritized action list

### P0 (this week - active campaign)
1. ChainDrop npm worm exposure sweep (wave active since 2026-08-04): freeze all dependency additions/updates until the pnpm hardening below lands; verify no workstation performed a non-frozen `pnpm add`/`pnpm update` since 2026-08-04 (check for unexpected Bun runtime installs, `setup.mjs` artifacts, unrecognized repos on our GitHub accounts, unexpected npm publishes); confirm CI remained `--frozen-lockfile`-only (it is, per ci.yml). ### P1 (next 2 weeks)
1. Migrate pnpm 9.12.3 to pnpm 10.x: adopt `onlyBuiltDependencies` allowlist (blocks lifecycle-script execution - the exact mechanism ChainDrop, Shai-Hulud 1/2 and the keyv wave rely on) and set `minimumReleaseAge` to at least 3-4 days so freshly-published (potentially worm-published) versions cannot be resolved.
2. Clear the 12 open `pnpm audit --prod` findings by bumping the stale root overrides (tar@7 >= 7.5.21, shell-quote >= 1.8.5, js-yaml@5 >= 5.2.2, js-yaml@3 >= 3.15.1) and adding image-size >= 2.0.3 and nanoid@3 >= 3.3.17; reinstall and re-run audit to zero. All are DoS-class in tooling chains, one critical (node-tar CVE-2026-59873).
3. Upgrade local dev Node v22.22.2 to v22.23.2+ (July 29, 2026 security release: HTTP/2 high-severity fixes, TLS session-reuse hostname bypass); spot-check the Vercel project reports a current nodejs22.x runtime. CI is already self-current.
4. Prompt-injection review of the AI document pipelines (PO scan, photo-to-ISBN, AI chat agentic reorder tools) against OWASP GenAI LLM Top 10 2026 and the Agentic Top 10: strict tool allowlist, human confirmation on all write-capable tool calls, uploaded/fetched content treated strictly as data, tool-call audit logging.

### P2 (this quarter)
1. GitHub Actions hardening: pin all five actions to full commit SHAs; add least-privilege `permissions:` blocks to ci.yml and security-scan.yml (prewarm-on-deploy.yml already has `permissions: {}`).
2. Enable EAS Update end-to-end code signing for the mobile OTA channel; verify Expo account 2FA; plan Expo SDK 53 -> 54 upgrade.
3. Recurring Supabase advisors (security lint) pass against prod after each migration wave; confirm platform Postgres patch level while there.
4. Subscribe the team to the Next.js pre-announced security release program (started July 2026) so future patch windows are scheduled rather than reactive; keep the react/react-server-dom floors from the Dec 2025-May 2026 advisories as hard minimums in review.
5. Stripe webhook signature-verification spot-check; keep stripe-node major tracked.
